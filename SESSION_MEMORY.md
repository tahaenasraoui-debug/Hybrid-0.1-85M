## 1. Project Mission & Invariants

1. Purpose: Build a custom causal transformer draft model (Hybrid-0.1-85M) from scratch in PyTorch, paired with the Qwen2.5 family (Qwen2.5-0.5B, Qwen2.5-1.5B, Qwen2.5-7B) for lossless speculative decoding.
2. Zero High-Level Abstractions: Implemented raw PyTorch attention, RoPE, RMSNorm, SwiGLU, KV caching, and Leviathan rejection sampling with zero dependency on `model.generate()`.
3. Lossless Fidelity Invariant:
   - For greedy decoding ($T = 0.0$), the output sequence generated by speculative decoding is mathematically identical to the target model evaluated autoregressively.
   - When Target == Draft, the acceptance rate is strictly 100%.
4. Hardware Guardrail: Peak resident GPU VRAM strictly under 2.8 GB during both training and speculative inference on the 3 GB GTX 1050 Mobile card.

## 2. Model Architecture: Hybrid-0.1-85M

- Parameters: ~85M (85,000,000)
- Vocabulary Size: 151,936 (exact Qwen2.5 BPE tokenizer compatibility)
- Hidden Dimension (d_model): 480
- Transformer Layers: 5
- Attention Heads: 8 Query heads, 2 Key-Value heads (Grouped Query Attention, GQA)
- Head Dimension: 60
- Intermediate Dimension (FFN): 1,280 (SwiGLU activation)
- Positional Encoding: Rotary Position Embedding (RoPE) with theta = 1,000,000
- Weight Tying: Output projection tied directly to input embedding layer (`wte.weight == lm_head.weight`), reducing memory footprint by ~73M parameters.
- Multi-token KV Cache: Implemented with dynamic sequence slicing and rollback support.

## 3. Lossless Speculative Decoding Engine

- File: `src/speculative.py`
- Cache Management: `speculative/cache_manager.py`
  - Handles both Hugging Face `DynamicCache` and native PyTorch tuples/lists of `(k, v)`.
  - Reversible rollback: uses positive index `cache.crop(target_len)` to avoid phantom token retention or cache pollution upon rejection.
- Rejection Sampling Algorithm (Leviathan et al., 2023):
  - Draft generates $k$ speculative tokens with draft KV caching.
  - Target model performs a single batched parallel forward pass over all $k$ candidate tokens.
  - Rejection point $i$: First token where target argmax differs from draft token (at $T=0.0$).
  - Correction: Target emits its correct token at index $i$, and KV caches for both models are rolled back to $i + 1$.
- Heterogeneous Execution:
  - Supports running draft model on GPU (CUDA) and target model in 4-bit NF4 (`bitsandbytes`) or offloaded to CPU.

## 7. Major Bugs Encountered & Solutions

1. `ModuleNotFoundError: No module named 'config'` inside `scripts/`:
   - Solution: Added `sys.path.insert(0, PROJECT_ROOT)` to resolve imports from root regardless of working directory.
2. CUDA Out of Memory (OOM) on 3 GB GTX 1050 during SFT:
   - Solution: Cleaned orphaned processes holding VRAM, switched to `bnb.optim.AdamW8bit`, enabled `torch.amp.autocast(dtype=torch.float16)`. Peak memory dropped to 1.05 GB.
3. Hugging Face Upload Script String Parsing SyntaxError:
   - Solution: Fixed unescaped markdown quote boundaries inside triple-quoted multiline strings in `scripts/upload_to_hf.py`.
4. Git Push Non-Fast-Forward Rejection:
   - Cause: Remote repository had 2 commits added on GitHub (adding MIT license and modifying README).
   - Solution: Rebased local branch on top of `origin/main`, resolved markdown header spacing conflict, keeping working tree clean and ready for fast-forward push.
5. Zero Emojis Policy:
   - Ensured all markdown files (`README.md`, `HF_MODEL_CARD`, `SESSION_MEMORY.md`) and CLI scripts contain zero emojis.
